# XIGRA｜隙格速记 · 产品设计与技术审查

**建议先修保存链路，再做记录界面。** 速记的默认入口是一张可立即输入的草稿。紧凑和展开两种视图共用记录 ID、选中状态、草稿与保存队列。用户从展开工作站仍可进入现有白板、文件和设置。本轮交付设计与技术审查，后续按批次确认和实施。

## 1. 当前问题与可复用能力

| 项目 | 当前行为与判断 | 优先级 |
| --- | --- | --- |
| 呼出与立即输入 | 主进程显示窗口并发送 `app:focus`，小窗在 `BoardClient.ready` 后聚焦正文。当前未明确区分首次捕获、已有未提交草稿和恢复旧选中项。默认回落到最后一个枚举的文本元素，直接输入可能改写旧便笺。客户端尚未准备好时编辑器禁用。 [小窗](../src/QuickPanel.tsx) · [主进程](../desktop/main.cjs) | P0 |
| 保存乱序 | `tick` 有 `busy` 锁，提交串行。服务端用 `expected` 版本及 `opId` 回执阻止重复和静默覆盖。这条保护应保留。但同一个操作发出后若未获回执，`inFlight` 在 `finally` 清空，后续编辑可能合并到已经提交过的编号。此路径已复现，见下文。 [客户端](../src/board.ts) · [服务端](../desktop/server.cjs) | P0 |
| 调度遗漏 | 输入时建立 150 ms 定时器。若它在 `tick` 等待最后一次 GET 时触发，忙锁会令回调直接返回，当前轮退出也未必重新调度。已复现队列有 1 条但没有新定时器，后续依赖另一事件唤醒。连续输入还会反复重置防抖。 [客户端](../src/board.ts) | P0 |
| 隐藏与异常退出 | `edit` 每次序列化完整 base、pending、conflicts，并异步请求 `saveRecovery`。`savedValue` 在 IPC 回执前即更新。Esc、按钮、托盘关闭路径和全局热键可直接隐藏，当前没有最新恢复写入的等待边界。历史强退用例在读到恢复副本后才退出，覆盖已落盘样本。对最后一次尚未获确认的字符仍需明确边界。 [恢复 IPC](../desktop/engines/install-services.cjs) · [强退用例](../tests/core-desktop.cjs) | P0 |
| 保存状态、冲突和重试 | 展示层用 `client.error/conflicts` 覆盖成功状态，这是有用的防线。但 `tick` 内部在 pending 清空后仍可将状态设为「已保存」，`flush()` 也仅按 pending 是否为空判断。离线文案未核对最新恢复回执。失败删除的值是 `null`，当前冲突缓冲只保留真值内容，失败删除可能丢失独立反馈。 [保存组件](../src/xigra/visuals.tsx) · [客户端](../src/board.ts) | P0 |
| 草稿身份与视图一致性 | 两种视图已共用同一个 `BoardClient`，往返可带回选中便笺。小窗和工作区仍分别维护选中 ID，光标位置未独立记忆。小窗对无内容的草稿不立即入库，画布新建命令会创建空文本元素。这两条路径需区分，速记采用一套草稿规则。 [视图切换](../src/main.tsx) | P0 |
| 查找与组织 | 工作站已有便笺列表和 Ctrl+K 首行定位。小窗缺少最近记录与全文查找。`TextValue` 没有创建或更新时间，也没有置顶字段。数组/对象顺序不能当作旧记录时间。 [记录模型](../src/board.ts) · [工作站](../src/main.tsx) | P0 查找，P1 置顶 |
| 中文输入法 | 渲染器快捷键已检查 `isComposing`，兼容检查也使用 `keyCode === 229`。正文没有独立组合缓冲，候选阶段的 `onChange` 仍可能进入保存。原生 `globalShortcut` 回调从主进程触发，当前直接隐藏时不经编辑器检查。 [快捷键](https://www.electronjs.org/docs/latest/api/global-shortcut) · [组合事件](https://www.w3.org/TR/uievents/#events-compositionevents) | P0 |

**审查探针结果**　直接加载当前 `BoardClient` 并连接仓库实际 `createStore` 内存状态机，控制回执与定时器时序。第一次提交在服务端应用成功后中断回执，随后修改同一便笺。新正文复用了同一 `opId`，服务端报告「操作编号重复」，第一稿保留在已提交数据中，最新稿进入冲突缓冲。第二条探针在刷新 GET 未结束时输入，等待原定时器触发再释放 GET，队列仍有 1 条且没有重新调度。探针验证了代码路径，本轮没有用它代替 SQLite 落盘、原生热键或实机输入法验收。

## 2. 推荐的信息架构

- **便签区**负责即时捕获。正文占主要面积，次要内容只放最近记录、搜索入口与保存结果。保留「切换到工作区」和现有快速投递入口。
- **工作区 → 便签**提供完整的记录列表与纯文本编辑。小窗展开后直接到这一页并保持当前记录。工作区的「工作页」继续打开现有画布，文件和设置维持现有入口。
- **搜索**用同一套文本匹配。小窗打开临时搜索弹层，选中结果即回到编辑器。展开态搜索留在列表顶部，结果更新时保留右侧当前正文，用户选择新结果才切换。
- **记录顺序**先显示待恢复稿，再按已知最近编辑/打开时间排列。旧记录时间未知时保留可搜索、使用稳定顺序，并省略日期。P1 置顶在完整列表中独立分组。

## 3. 两种布局与关键交互

优先采用「单列速记 + 展开双栏」。另一个可行方向是在小窗也常驻左侧列表，但 400 px 下会缩短正文行宽，并让选择与输入竞争注意力。小窗用统一左边线和 16 px 页边，保持单一正文滚动区。展开态保留导航和左右两栏的职责。样式直接使用现有 XIGRA Tokens，正文 16 px、列表 14 px、状态与摘要 12 px。默认单一强调色、可见键盘焦点和统一的按钮反馈。

小窗最多两条最近记录。400×460 内容区降为一条，错误提示展开时将摘要折为「最近」入口，编辑器和底栏始终可达。展开态建议列表 248–272 px，正文占剩余空间。P1 的复制在正文动作区，置顶和删除撤销放到管理菜单；P0 的删除先在工作区提供可识别的确认。受限宽度优先保留编辑、搜索和返回，复杂动作进入工作区。

尺寸均指渲染内容区。沿用当前 620×700 默认外框与 500×540 最小外框。测试 400×460 时仅调整隔离测试窗口的尺寸限制。

| 动作 | 约定 |
| --- | --- |
| 全局呼出 | 隐藏→显示时，优先打开上次未确认的草稿并聚焦正文；干净的全新捕获会话进入空草稿。窗口已经显示、只是失焦时恢复当前记录和光标。显式往返模式属于同一会话，保留选中项、未提交文本与光标/选区 |
| 立即输入 / 新建 | 连接准备期间接受内存草稿并提示「正在连接 · 尚未落盘」。首个有效输入为该草稿分配一个稳定 ID，空白草稿不入库。只含空格的编辑缓冲保留输入体验。准备好后自动把最新值交给队列。切换前先固定编辑目标 ID |

## 4. 数据流与保存状态

```text
键盘 / IME → RecordEditor 的输入缓冲 → 记录会话（ID、选中项、光标）
                                      │ 组合完成、有效正文
                                      ↓
紧凑与展开列表 ← BoardClient.view() ← BoardClient.pending
                                        ├─ 现有 /api/ops → 版本校验 → SQLite 提交 → 回执
                                        └─ 现有 saveRecovery → SQLite 恢复副本 → 回执
```

**一套记录写入。** `BoardClient` 继续拥有 `base`、乐观视图、操作版本和冲突队列。UI 草稿只承担组合输入和服务未就绪的内存缓冲。已进入队列的记录不维护第二份可写数据库或独立 localStorage 记录。打开不同界面时复用同一会话，未确认的操作仍属于原记录 ID。

**队列修正。** 只允许合并从未发出的最后一条同记录操作。操作一旦发出，其 `opId`、`expected` 和正文冻结到成功或终止。恢复来的未确认操作按可能已发出处理。新的输入排在后面。`tick` 结束时检查是否有新增待发项，保证存在续跑任务。保留短防抖，并设连续输入的最长提交间隔，起点建议 1 s。断线用有限间隔重试，恢复网络或按「重试」立即调度同一队列。永久错误和版本冲突保留相关记录、删除意图与错误原因，不阻塞无关记录继续提交。

**恢复写入。** 在渲染器端按单路写入恢复副本，同一时间一个请求，未发的快照合并到最新一代。记录实际获回执的代数，旧回执和旧失败不能改变新草稿的状态。恢复内容仍用现有 IPC 和 SQLite 存储，遵循现有 24 MiB 上限。失败时保留内存和复制出口，不静默截断正文。重启先校验恢复形状和 `roomId`，同房间继续按原操作重放。房间不匹配时保留可取回内容，禁止回放至新白板或自动覆盖唯一恢复副本，留给用户确认迁移或复制。

| 显示 | 可验证的触发条件 |
| --- | --- |
| 等待输入 | 尚未创建可提交记录 |
| 尚未落盘 | 当前修改只在内存，或最新恢复副本尚未收到回执 |
| 保存中 | 当前记录有待发或在途操作，正常提交正在推进 |
| 已暂存 · 待同步 | 当前记录最新恢复副本已确认，记录提交尚未获回执 |
| 已保存 | 当前记录最新版本已收到数据库提交回执，且没有更新的编辑或未解决冲突 |
| 保存失败 / 有冲突 | 当前记录存在恢复写入失败、永久提交错误或版本冲突。提供重试、复制或恢复入口。删除失败单独提示 |

反馈优先按当前记录判断，冲突和未解决失败优先，其次按最新版本是否已提交、恢复副本是否已确认区分。正常提交且恢复写入尚未确认时，可合并显示「保存中 · 尚未落盘」。已经提交的正文无需等额外的恢复副本才显示「已保存」，旧恢复请求的迟到回执或错误也不能覆盖这个结果。

**隐藏和系统边界。** 从编辑器触发的 Esc 和隐藏按钮先结束合法的组合输入，再请求当前恢复写入尽快推进。等待本地确认采用短上限，不等待局域网回复。保护策略是最新草稿还未确认且写入失败时留在原位并提供「重试／复制」，之后可由用户主动处理。现有原生热键、窗口关闭与 `before-quit` 路径目前没有渲染器确认。完整支持这些路径需要单独批准最窄的隐藏/退出意图与确认桥，按会话代数拒绝过期回执。主进程超时仍没有安全确认时保留窗口，并提供明确退出路径。强杀或系统关机不能依赖退出回调补写，恢复保证以最后一次持久化确认的版本为界。 [Electron 应用生命周期](https://www.electronjs.org/docs/latest/api/app#event-before-quit)

**最近记录与置顶。** 首版搜索用已有内存快照，扫描有效文本，不处理笔迹和文件。最近顺序以实际打开或编辑事件计算，推荐随现有恢复 JSON 保存一个最多 32 项的可选桌面本地 ID 顺序。这样重启能找回最近使用的记录，无需增加数据库字段或更改现有 IPC 形参。兼容旧值，按 `roomId` 隔离，剔除已删除 ID，保存失败时回落到当次会话。恢复旧备份可能重置这些本地偏好。置顶同样建议先按设备本地保存，等 P1 确认。没有时间数据的旧条目不编造日期。

### P0a 实施结果
