# 关系画布与导航：视觉秩序精修

## 范围与参考边界

本轮仅精修左侧导航、关系画布及该页顶部/工具浮层。保持石墨灰和蓝紫强调色，不改后端、数据模型、节点世界坐标、画布缩放逻辑或业务行为。便签、文件、自由工作页等待用户确认后再扩展；旧主题系统批次不自动执行。

本条消息没有可读取的Arasn/Codex截图附件，因此不能声称完成两款应用的截图级比较。实际审查基于当前Arasn真实Electron截图和代码；“更连续的表面、低权重导航、聚焦内容”来自用户描述的目标，而非对未见Codex截图的事实判断。web-design-guidelines技能未安装，使用frontend-design与本地visual-qa完成检查。

## 实际问题清单

| 区域 | 修改前实际问题 | 处理 |
| --- | --- | --- |
| 页面外壳 | 顶部栏分隔、画布外框、内部工具栏分隔叠加，主区像嵌入另一块应用 | 移除关系页重复边框，顶部与导航延续同一背景，画布靠明度区分 |
| 顶部操作 | 整理、设置、搜索、类型、新建和历史都在竞争注意力 | 普通动作透明背景，输入使用弱边框，新建为唯一实底主操作 |
| 侧栏 | 208px侧栏选中项大面积高饱和色，与画布节点争夺焦点 | 低饱和底、可读文字及细强调条；键盘焦点仍独立显示 |
| 节点 | 15px标题/12px正文/10px底部，正文偏小，底部横线让摘要再次分层 | 标题16/24、正文14/21、底部11/16；删除底部装饰线 |
| 画布 | 点阵与节点细线同时出现，浅色偏蓝、深色点阵较醒目 | 缩小点径并降低灰阶对比，保留原网格间距和位置逻辑 |
| 浮层 | 节点操作条、属性面板、小地图和缩放条的边框/阴影各不相同 | 统一Floating Surface、细边界与双层阴影；保留全部原操作 |
| 中屏 | 类型/搜索/按钮宽度合计过大，历史操作被挤出第三行 | 调整搜索弹性宽度和工具间距，使820px工具区收敛 |

## 设计方向与规范

比较三种方向：继续强化面板边界（仍会拼接）、全部扁平化（削弱浮层与焦点）、连续工作表面（采用）。以导航/应用灰阶承托画布，以卡片亮度承托正文，以有限阴影表达悬浮，仅让主要操作及当前焦点保持较强蓝紫对比。不增加组件，不靠缩小点击区域实现极简。

新规范集中于src/visual-order.css。所有值均为本轮Arasn选择，未声称复制Codex数值。

| Tokens | 规范 |
| --- | --- |
| Layout | --ui-space-1/2/3/4/6 = 4/8/12/16/24px；控件36px，原导航44px保持 |
| Typography | title18、content16、body14、control13、meta12、small11；内容行高24、正文21；沿用现有字体链 |
| Radius | 控件7、内容10、浮层12px |
| Border | subtle用于卡片/浮层细边界，control用于输入；移除区域之间无意义的矩形线 |
| Shadow | card低位阴影，floating更宽但低透明度的阴影；不依靠高饱和大背景塑造空间 |
| Accent | 导航active低饱和，主操作实底，选中节点边界+轻光晕，focus独立外轮廓 |

## 实际验证

- npm run build通过，含TypeScript与LAN bundle；原有构建警告仍在。
- visual-order-desktop通过：固定五个节点、四条关系、相同正文/世界坐标/节点尺寸，1440×900、820×700、390×720，浅/深色，100%与64%，节点选中、属性面板、键盘焦点。另检查140px高节点各文本区域位于节点内。
- 8组before/after的fixtureHash、窗口宽高及缩放标签逐项一致。因工具栏高度/外框被精修，视口中心在屏幕上的位置有少量变化；没有为了让截图好看修改节点排布或缩放倍率。
- topology-desktop通过：五种类型/状态、原记录保留、负坐标、拖动历史、锚定缩放、小地图、重启、恢复、窄屏导航、双击与减少动效。
- relation-motion-desktop通过：关系语义色、标签对比度、箭头/连线/动画同色、操作条尺寸、锚点、菜单/Escape、双向/无向、减少动效与100/300节点降级。该测试包含短时帧间隔样本，不将其当成长稳性能结论。
- sidebar-desktop通过：导航/分组、hover与active区分、键盘激活、文件/设备/设置、主题回归及1440/820/390边界。
- 本轮生产改动仅样式与class，未重复执行所有存储单测，不声称全量回归。
