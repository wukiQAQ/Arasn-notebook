# 触发可视化与引导计划

## 审查

Electron 主进程维护 `BrowserWindow` 和 `WindowManager`。Windows 键盘通过 `RegisterHotKey` 注册。鼠标按键、手势及热区共用一个 Raw Input 接收者。注册表以版本 1 的绑定列表保存配置，沿用先检查、再持久化和切换注册的流程。手势录制和原生识别共用 `GesturePath`。热区检测使用 Windows 物理工作区与 Electron 显示器缩放，避开任务栏和共享边界。

`TriggerSettings` 已通过 IPC 拿到真实配置、能力与注册失败状态。现有热区选择为九宫格，手势录制已有实时线条，保存后的手势没有轨迹图。第一批可复用设置分类、动作分组、表单、颜色、焦点及减少动态效果。图形按配置绘制，不需要原生层传光标坐标。

第二批可沿用注册表的测试模式与手势识别，补充手势失败原因和热区候选进入、取消及命中事件。主进程只发布候选状态和开始时间，前端据此展示进度。原生停留计时仍由主进程负责。高频指针事件留在原生层。退出设置或测试时清理订阅，避免测试命中派发真实动作。

## 信息架构

考虑过独立的设置向导、跟随表单的并排预览，以及现有设置内的显示器图与就地编辑。第一批采用第三种，在窄窗保持单列。对办公用户先呈现位置、按键或方向，再展开参数。使用现有 Graphite Blue 强调色、中性工作区、原有字体与 6／8／12 px 间距。热区颜色同时配合文字状态、选中描边和可见焦点。

六步引导依次为认识 Arasn、选择并实际配置呼出方式、尝试屏幕热区、写便笺并复开确认、暂存用户选择的文件、完成与查看帮助。每步保留返回、暂停和跳过入口。便笺复用自动保存状态，文件练习走现有投递槽。新用户首次进入轻量入口，续看及版本提示走持久状态，现有用户的绑定与记录由原入口管理。

| 批次 | 文件与职责 | 验收 |
| --- | --- | --- |
| 1 可视化 | `TriggerSettings.tsx` 接入 `TriggerVisuals.tsx` 与 `triggers.css`。新增热区图、按键图和保存手势的方向轨迹。 | 图形显示现有绑定、鼠标和键盘可选区域、编辑宽度即时改变、亮暗与窄窗、演示期间无业务派发。 |

| 4 帮助 | 在设置加入帮助入口，复用三种可视化和实际动作说明。 | 键盘导航、主题、减少动效、帮助文案与真实功能一致。 |

## 第一批交付

- 屏幕图显示八个区域，突出已启用、悬停和当前选择。点击可打开该区绑定，宽度、停留与冷却和表单共用同一份草稿。色带用放大示意宽度，实际设定仍以 Windows 逻辑像素（DIP）为准。切区前保留有修改的草稿。同一区域有多条保存记录时，图上优先显示已启用记录，各记录仍可从动作分组编辑。
- 停留与冷却演示只驱动当前图形与状态文本。鼠标图标注五个按键并读取启用状态，手势图用保存的方向序列画出起点与箭头。
- `npm run build`、27 项 Node 测试、`node tests/trigger-visuals.cjs` 和 Windows 原生触发回归 `node tests/trigger-desktop.cjs --mouse --smart --edge --feedback` 均通过。已检查亮色桌面、深色与 390 px 窄窗截图。几何单测覆盖混合缩放与接缝，物理双屏和不同 DPI 待实机验证。

本轮到第一批为止。接续第二批时先明确热区候选事件的订阅和退出语义，并将图内演示与 Windows 系统测试分开。
