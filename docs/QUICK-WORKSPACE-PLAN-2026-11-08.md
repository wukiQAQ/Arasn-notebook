# Arasn 轻泊 · 产品与架构规划

评审基线为当前工作区的轻泊 0.6.0，首发范围按现有交付假定为 Windows x64。文中的产品行为、容量和性能指标均为拟定验收条件。本轮依据源码、已有截图和历史测试记录，实施范围等方案确认后再确定。

## 0. 现状审查

当前使用 Electron 45.2.1、React 19、TypeScript、Vite、Base UI 和 Lucide。Windows 安装由 electron-builder/NSIS 负责。Electron 主进程拥有窗口、托盘、权限和服务，沙箱渲染器通过 preload 白名单 IPC 操作文件与系统能力。桌面白板目前由本地 HTTP 环回端口提供 UI 与 API。持久化使用 `worker_threads` 中的 `node:sqlite`，`workspace.sqlite` 保存元数据与操作，原件以 UUID 命名存放在 `objects/`。可继续使用现有安装与数据目录。 [版本与命令](../package.json) · [主进程](../desktop/main.cjs) · [预加载桥](../desktop/preload.cjs) · [存储实现](../desktop/engines/storage-worker.cjs)

| 能力 | 当前代码和证据 | 对新目标的差距 |
| --- | --- | --- |
| 呼出、托盘与小窗 | 单实例、自定义 `Ctrl+Alt+N`、注册冲突保留旧键、关闭隐藏、恢复窗口位置、展开/收回、显示后通知渲染器聚焦。默认小窗 520×640 DIP | 初次启动先等存储初始化。重复热键、焦点回到原应用、输入法、多屏与混合 DPI 需要实机验收。位置恢复应按实际窗口宽高重新约束，分别保存两种尺寸 |
| 便笺 | `QuickPanel` 有多便笺选择、新建、复制、样式。完整页有便笺查找及删除。`BoardClient` 以 150 ms 延迟合并提交，保存待发操作，支持版本与冲突恢复 | 便笺模型仍是带坐标的画板元素，缺独立时间字段。桌面写入沿用白板 HTTP 操作队列。小窗应以输入为第一层，记录列表、可见保存状态和失败恢复需要收敛 |
| 文件中转 | `FileStation` 可拖入、多选、分类搜索、分页、重命名、导出、引用、回收站及恢复。Worker 流式复制、计算 SHA-256、临时文件同步后改名并提交数据库，有备份和中断恢复 | 列表目前按时间排序，PNG/JPEG 是受限缩略图，不等于完整图片预览。缺少统一的预览、系统打开、复制取用路径与定位入口。补充磁盘配额、字节上限、取消及维护互斥测试 |
| 局域网 | 显式开启后监听 `0.0.0.0`，以随机 Bearer 链接访问同一个白板 store 的 `/api/board`、`/api/ops`。原功能共享文字与笔迹，文件留在本机 | 缺设备发现、双向身份确认、加密、逐次接受、文件流与传输回执。旧共享不能充当新传输协议 |
| 验证基线 | 历史打包程序通过文件导入、回收站、剪贴板与重启恢复。历史有浏览器双客户端白板回归。轻泊截图覆盖小窗与不同视口 | 尚缺新版物理热键到输入的延迟、两机真实传输、断网切换、磁盘满、长期驻留及安装向导验收 |

现有缩略图入口按实际头部识别 PNG/JPEG，输入上限 20 MiB，生成目标为 160×120，输出上限 256 KiB。导入支持一批至多 100 个普通文件。两者应分别保留自己的限制，导入能力无需随预览格式变化。旧白板与新功能须共享一次本地写入和恢复机制，避免出现两个可写副本。 [小窗](../src/QuickPanel.tsx) · [白板客户端](../src/board.ts) · [文件列表](../src/FileStation.tsx) · [旧共享服务](../desktop/server.cjs) · [历史核心验收](CORE-VALIDATION.md) · [轻泊实装记录](LAGOON-IMPLEMENTATION-2026-11-04.md) · [小窗截图](screenshots/redesign/lagoon-final/quick-text.png)

## 1. 产品需求

**定位**　一个可随时呼出的个人临时工作空间。用户从当前应用抄下念头或存放手边文件，通过搜索快速取回，需要时点对点发送给另一台设备。核心任务结束后用同一个快捷键或 Esc 收起，回到原应用。

**用户**　经常在浏览器、文档、会议和资源管理器之间切换的办公者、学生及开发者。优先覆盖个人单机和同一私有网络内的少量自用或可信设备。

| 场景 | 最短路径 | 用户能确认的结果 |
| --- | --- | --- |
| 会中记一句话 | 全局快捷键 → 输入 → 收起 | 已保存状态，重新呼出或重启可在最近记录找到 |
| 临时收几份文件 | 打开面板 → 任意空白投递区拖入 → 继续工作 | 看到每个文件的复制结果，源文件留在原处 |
| 找回记录或文件 | 最近 / 搜索 → 选中 → 复制、预览或打开 | 文件名、大小、时间与当前状态清楚可见 |
| 发到另一台电脑 | 选择项目 → 选已配对设备 → 对方接受 | 双方可查进度，接收成功后项目出现在接收方本地 |

MVP 的记录采用纯文本、多条独立记录、创建/编辑/删除/搜索/复制，支持换行和粘贴。标题可由首行派生，列表显示最后修改时间。旧样式与笔迹由兼容画布保留。文件提供批量拖入、分类和基础排序、名称搜索、回收、图片预览及取用。用户发起传输时只选择当前条目或多选项。设置提供快捷键、主题、置顶等少量必要项。

范围外包括账号、云盘、实时同步、团队空间、在线 Office 转码、复杂富文本、后台监听剪贴板、文件夹镜像和跨网穿透。保留现有主动粘贴、导出及备份能力，放在相应菜单内。

## 2. 优先级与路线

| 阶段 | 交付与依赖 | 放行条件 |
| --- | --- | --- |
| M1a 呼出和保存 | 测量现有常驻小窗。增加窗口状态协调、纯文本默认视图、便笺查询与时间字段。保留旧数据与本地画布。先打通写入确认和失败恢复，再简化工具条 | 物理热键、焦点与输入法验收通过。已确认保存的记录在异常退出后可读。旧样本迁移和恢复验证通过 |
| M1b 文件本地闭环 | 复用复制、回收站和备份。增加进度、排序、全窗投递、PNG/JPEG 详情预览、系统打开/导出。补齐资源边界与恢复。依赖现有文件 ID 和可复用的 staging/commit 边界 | 文件拖入、重启、预览、取用与删除验收通过。断网、空间不足及异常退出均能继续本地操作 |
| M2a 设备与文字 | 独立设备发现、手动地址、身份配对与撤销、接收提示。接入文字收件与幂等回执。以 M1 的记录写入边界作为依赖 | 两台真实电脑验证发现、配对、断网重试和拒收。未配对连接拿不到内容 |
| M2b 文件互传 | 复用 M1b 的对象发布和入库规则，增加选中项目清单、流式传输、配额、取消、错误定位、失败项重试 | 两机文件哈希一致。中断、拒收、回执丢失和低磁盘空间的场景无可见半成品或重复文件 |
| M3 体验完善 | 先验证锁定运行时的 PDF 和音视频，再按资源预算开放。之后完善搜索、分类、设置、微交互和长时间驻留 | 发布明确支持矩阵、系统打开回退、性能复测与安装升级验证 |

对个人开发者，建议按可独立回归的小批次推进。M1 风险主要在旧数据、原生焦点和文件落盘。M2 的时间主要花在身份、网络异常和真实两机验证。先跑通两机文字发送，再决定文件发送的规模上限。M3 的格式接入逐个放行。最少一轮旧包→新包→备份恢复演练随 M1 执行，安全检查贯穿每个阶段。

## 3. UI 与交互方案

信息架构为 **速记 / 文件** 两个常驻页签，顶栏提供搜索、展开及收起。记录列表在搜索或展开后显示，文件多选后出现批量操作。M2 的设备与传输使用从选中项发起的选择器和按需打开的任务历史。画布、主题、快捷键、备份与恢复放在次级入口。文件从任一页签拖入，浮出投递提示，成功后可选择前往文件页，当前便笺继续保留焦点。

### 两种布局

```text
A  窄窗直写，按需展开                      B  双栏常驻，边找边看
┌─ 速记  文件 ── 搜索 · 展开 · 收起 ┐      ┌─ 速记  文件 ───────── 搜索 · 收起 ┐
│                                  │      │ 最近 / 分类 │ 当前记录或文件详情 │
│  直接输入                         │      │ 列表与多选   │ 正文 / 预览        │
│                                  │      │             │                   │
└─ 保存状态 ──────── 最近记录入口 ──┘      └─ 导入/传输进度 ──────────────────┘
```

| 维度 | A · 单栏速记，默认 | B · 双栏工作区，展开态 |
| --- | --- | --- |
| 操作效率 | 约 480×560 DIP 起步，呼出即可打字。最近记录和大批量操作需要一次展开 | 约 900×640 DIP 起步，连续浏览、编辑与批量选择可在同一屏完成 |
| 视觉清晰度 | 一个主区域，文件页和编辑页各自专注，遮挡少 | 列表与详情保持上下文，狭窄工作区需自动切回单栏 |
| 扩展性 | 适合日常高频捕捉，复杂操作进入展开态 | 适合预览、分类和发送任务，常驻时更容易挤占原应用 |

推荐 **A 默认，B 作为同一窗口的展开态**。共用列表、编辑器、选择状态和数据层。不同窗口布局各自记忆尺寸，切换只改变显示方式。建议展开宽度至少 760 DIP 后启用双栏，阈值由长文件名、DPI 与键盘测试调整。

### 高频动作与状态

| 流程 | 默认与反馈 | 失败及恢复 |
| --- | --- | --- |
| 呼出与返回 | 隐藏→显示时焦点进空白速记，上一草稿保存失败时先恢复它。可见且在前台再次按键即隐藏，可见但失焦则拉回前台。托盘另有直接进入文件的入口。使用 OS 自身的焦点交还，记录实际成功率 | 冲突保留旧键，托盘始终可打开设置。避免仅因失焦关闭，输入法候选、文件选择、拖拽和系统弹窗不触发隐藏。原应用关闭或系统拒绝切焦时允许用户自行切换 |
| 记录与保存 | 空白提示“直接输入”。首个有效输入创建一条记录。输入立即回显，底栏依次显示“保存中”“已保存”。Esc 先关菜单/预览，下一次再收起，输入法组合期间交给输入法。`Ctrl+Enter` 等确认后收起 | 保存失败保留正文，提供“重试”和“复制内容”。正常退出有限等待，仍失败则让用户选择返回或确认退出。崩溃前尚未提交的字符不承诺恢复 |
| 查找与删除 | 最近按更新时间，搜索覆盖全文，时间对未知旧记录显示“旧版导入”。行悬停显示动作，选择有文字或勾选状态。删除前展示对象，旧画布中同一条记录同步更新 | 无匹配时保留查询并可清空。旧画布的同一条记录只能通过同一写入链变更。读取失败保留最后可用列表并可重试 |
| 拖入文件 | 面板可见时接收拖放，文件进入时高亮投递区，松手显示逐文件与总进度。完成显示“已保存 3 个文件”。空列表提供“拖入文件或选择文件” | 部分失败分开显示，重试只处理失败项，明确区分无权限、文件变化与空间不足。导入过程中收起，任务继续并可在再次打开后查看 |
| 预览与打开 | 选中文件出现真实名称、类型、大小与时间。Enter 打开安全预览，支持系统程序时提供有文字的“打开副本”。预览加载有占位，退出时回到所选行 | 不支持、文件损坏、系统缺少关联程序分别提示，可保存副本。导出完成提供“复制路径 / 在文件夹中显示” |
| 发送与接收 | 选择后出现“发送”，设备列表显示已配对/在线/不可达。接收方看到发件人、项目名和总大小，主动接受。默认通知不抢焦点，进度写入历史 | 拒绝、取消、超时、空间不足、校验失败各有状态。重试复用同一传输 ID，确认后只补失败项。无网络继续速记、文件和搜索 |

**视觉规范**　沿用轻泊的中性纸面与莓灰。浅色建议背景 `#F3F1F3`、表面 `#FFFFFF`、主文 `#343039`、次文 `#625B67`、强调 `#7C5974`。暖深色建议 `#242323` / `#302F2E` / `#F1E9DE` / `#BDB3A9` / `#E4B58A`。状态用文案和符号共同表达。正文 15–16 px、列表 13–14 px、元数据 12 px。正文优先系统字体和中文回退，现有 Manrope 用于品牌。间距 4/8/12/16/24 px，窗口内表面圆角 12 px，控件 8 px，文件行至少 40 px，主操作命中区至少 36 px。弹出层一档阴影。键盘焦点清晰，缩放后文字仍可读，光标跟随不做动画。转场建议 120–160 ms，减少动态效果时直接切换，窗口显示与输入响应不等待动效。设计值需在两种主题、最小窗口及 125%/150% DPI 下复核。

## 4. 技术架构

### 技术栈选择

| 选择 | 收益 | 代价与判断 |
| --- | --- | --- |
| 继续 Electron | 可复用现有托盘、快捷键、React、Node 流、SQLite Worker、原生桥、测试和安装包。统一 Chromium 渲染，当前能力最完整 | 包体、内存和 Electron 安全更新需要持续管理。优先测量并优化单窗口、延迟初始化和后台空转，推荐用于 M1–M3 |
| Tauri | 使用系统 WebView，有机会降低分发体积。React 视图可部分迁移 | Windows WebView2、macOS WKWebView、Linux WebKitGTK 的预览和焦点行为须分别验证。现有 Node 服务需改写或保留 sidecar，并重新验证持久化、打包与升级。先用实际测量判断是否值得做单功能试验。 [Tauri WebView 文档](https://v2.tauri.app/reference/webview-versions/) |
| Windows 原生 | 可直接针对平台窗口、热键、托盘与系统打开行为调优 | 需要重写 UI 和桥接，双栈维护成本高。仅当实测关键目标持续不达标且决定长期只做 Windows 时再评估 |

历史安装包约 116 MiB。此前 0.6.0 的单机历史样本约 763 ms 启动到文件页、约 381 MiB 多进程工作集总和、4.50 ms 的 `showInactive/hide` 调用 P95。后两者分别含重复共享页的可能性，以及缺少物理按键、焦点和渲染的测量盲区。本轮以这些数据定位测量缺口，发布指标以下面的实机标准为准。 [历史基准](CORE-VALIDATION.md) · [包产物定义](../electron-builder.cjs)

### 模块、权限与数据流

```text
物理热键 / 托盘 → WindowManager → 同一个小窗 / 展开态
React UI → preload 白名单 IPC → 桌面命令路由
                                 ├─ NoteService → PanelEngine ─┐
                                 ├─ FileEngine ────────────────┤
                                 ├─ PreviewService → 文件 ID  │
                                 ├─ 设置与恢复 ────────────────┤
                                 └─ TransferService → 入库 ───┤
                                                               ↓
                              StorageEngine / Worker → SQLite + staging + objects
```

| 模块 | 职责与依赖 |
| --- | --- |
| WindowManager | 注册、托盘、展示状态、焦点调度、展开尺寸与屏幕约束。把用户设置和当前窗口状态分开。窗口以实际 DIP 尺寸按工作区约束，处理屏幕拔插、休眠恢复和位置保存。只预热一个窗口 |
| NoteService | 查询纯文本、版本检查、时间与最近列表。通过现有 PanelEngine 进入同一 Worker 事务，提交后更新快照与事件，避免画板视图出现旧状态 |
| FileEngine | 文件 ID 与列表、导入、导出、删除/恢复、任务进度。业务 ID 解析与文件 I/O 在可信端，打开入口有明确用户动作。重用 RecoveryService 与操作日志 |
| PreviewService | 查询 ID 与权限，识别格式，按需解码和有限缓存。独立沙箱查看器获取受限字节流，预览异常回退到文件详情。文件列表按可见行请求缩略图 |
| Discovery / Transfer | 设备发现只输出候选端点。传输服务负责身份、请求、限额和任务状态。使用 Node 流与背压在可信层写 staging，再通过存储命令提交；渲染器只收到任务摘要 |
| StorageEngine / 配置 | SQLite 单一写入入口，迁移、恢复、数据完整性。业务配置放 `settings`，设备密钥加密后保存，备份与日志排除密钥与配对授权 |

冷启动把数据库恢复留在 Worker，托盘和快捷键可提前就绪，窗口在恢复期间显示可辨识的加载状态。常驻路径直接复用已加载窗口。首页按需加载画布、文件详情和预览，关闭预览时取消解码或媒体流。保留事件驱动的本地刷新，文件与传输进度合并推送，配对监听按需启动。先测量首帧、可输入和私有工作集，再针对实测瓶颈调整缓存与模块加载顺序。

拟定 IPC 契约如下。参数在主进程按明确类型、长度、枚举与发送方校验。事件以任务 ID、记录版本或序列号更新界面，窗口重新打开时先拉取快照。文件内容走受控流，不经通用 IPC 传大块 Buffer。

| 命令 | 输入与结果 |
| --- | --- |
| `window:show` / `window:hide` / `settings:patch` | 指定目标页或设置白名单，返回显示状态或成功设置。逐步封装现有 `app:*` 桥 |
| `notes:list` / `notes:get` / `notes:save` / `notes:delete` | 查询与游标 / ID / `id, expectedVersion, mutationId, body`。提交返回 `id, version, updatedAt`。删除使用预期版本，列表更新用提交事件 |
| `files:list` / `files:choose` / `files:drop` | 筛选、排序、分页与选择。接收由系统选择器或可信拖放桥产生的本地文件。结果含任务 ID、成功与失败的条目。文件动作按需收敛为 ID 接口 |
| `preview:open` / `preview:close` / `files:export` / `files:openCopy` | `fileId` → 可关闭的短时预览令牌或明确位置的副本。令牌限定窗口、会话、类型和读取范围，关闭、删除或退出时失效 |
| `transfer:peers` / `pair` / `offer` / `respond` / `cancel` / `retry` / `list` | 候选设备、配对状态及任务摘要。发送仅提交已选的记录/文件 ID，接收按任务 ID 明确批准。敏感凭据、原件路径和绝对目录留在可信端 |

统一错误结构使用 `code, message, retryable, taskId?`。例如 `SHORTCUT_IN_USE`、`VERSION_CONFLICT`、`DISK_FULL`、`SOURCE_CHANGED`、`PREVIEW_UNSUPPORTED`、`PEER_UNREACHABLE`、`HASH_MISMATCH`。重试传递操作 ID，版本冲突显示草稿并给出复制或另存为新记录的出口。诊断日志记录阶段与错误码，避免记录正文、令牌、私钥或原始路径。保留现有 sandbox、context isolation、导航限制、CSP 和 sender 校验。重点收紧拖放桥、可调用动作及预览协议。先保留 loopback 加载和旧画布接口，逐步把速记的桌面写入收敛到 IPC。 [Electron 安全建议](https://www.electronjs.org/docs/latest/tutorial/security) · [Electron 协议 API](https://www.electronjs.org/docs/latest/api/protocol)

### 数据与可靠性

- **记录**　复用 `elements` 中的现有文字及 `version`，通过附加 `note_meta` 存储创建时间、更新时间与必要的排序字段。旧记录保留 ID、内容、样式、笔迹与坐标。无可靠时间的字段保持空，记录迁移时间供诊断。新增/编辑/删除走同一事务，生成快照的旧 API 及缓存随提交更新。初期用有界、参数化、转义通配符的全文包含查询和分页。只有实测长列表超预算后再引入额外索引策略。
- **保存**　保留防抖并对连续输入设最大提交间隔，建议 1 s。对有待保存内容的收起、切换、正常退出立即请求提交或保存恢复快照。恢复日志逐条更新未提交的便笺操作，避免每次输入重新序列化整个白板。只有数据库确认提交后显示“已保存”。存储 Worker 退出时进入故障状态，保留草稿和可复制出口，重启恢复后再接收新任务。
- **文件**　按实际读取字节限制，源文件只读。普通文件句柄固定后再流式复制并复核，符号链接与重解析点按平台测试后决定接受策略。写同卷 `.part`、校验大小和 SHA-256、同步文件、改名、提交 SQLite，发布成功事件后列表才显示。数据库与文件系统之间用操作日志和启动对账恢复，特别覆盖改名成功、数据库提交失败留下的孤儿对象。删除先软删除，清空回收站继续走显式确认和备份。文件正文、哈希、预览缓存不复制进渲染器状态。
- **取用**　系统打开和导出按展示名创建可安全识别的副本。复制路径、在文件夹中显示指向用户已导出的副本，首次操作可先选保存位置。临时打开副本独立管理生命周期，入口清楚标注“副本”，预览缓存可重建。对已接收文件保留来源信息，按平台验证下载来源标记。可执行文件、脚本和活动内容提供显式导出入口。
- **迁移与回滚**　兼容旧 `board.json` 与现有数据库。先做一致性备份，再事务性增量迁移，升级 schema 与备份恢复校验一并验收。应用检测到未知 schema 时给出恢复入口。回退用升级前备份另开数据目录，回退前先导出新版新增内容。兼容层和备份升级路径通过后再考虑删除旧代码。

### 局域网协议与安全

1. **发现**　用户开启接收后启动局域网服务。使用 mDNS/DNS-SD 发布服务版本、昵称、短期发现 ID 与端口。发现信息仅用于连接候选。按 TTL 标识离线，休眠恢复和网卡变化后重建监听。手动输入地址/端口作为备用，设备隔离或防火墙拦截仍应明确报告不可达。只监听所选私有网卡，停用接收后关闭广告和监听。优先验证 IPv4 私网，IPv6、多网卡与 VPN 按实机矩阵逐项开放。 [DNS-SD 规范](https://www.rfc-editor.org/rfc/rfc6763)
2. **身份**　各设备生成独立身份密钥和证书。首次在短时配对窗口中建立仅允许配对的 TLS 会话，双方通过可信的带外方式核对对端完整证书或公钥指纹，再保存授权。配对窗口限制并发、次数和时长。后续双向验证固定身份，证书变化重新确认，撤销后立即断开并拒绝后续请求。认证前不开放业务路由。私钥由 Electron `safeStorage` 所在平台的安全机制保护，安全存储不可用时保持本地功能并停用长期配对。采用运行时支持的 TLS，禁用明文回退。先做两机 TLS 与指纹校验试验再定具体库和证书生成方式。 [Node TLS](https://nodejs.org/api/tls.html) · [Electron safeStorage](https://www.electronjs.org/docs/latest/api/safe-storage)
3. **授权与传输**　走独立传输服务，配对后的发送方提交 `transferId` 和选中项清单，清单只含需要展示的名称、类型、大小和哈希等元数据。接收方对这次清单接受后签发短时、一次性的上传授权，限定设备、任务、项目和字节数。传输协议可用版本化 HTTPS `offer → accept/reject → upload → status`，记录正文为有界 UTF-8，文件为字节流。接收端无需暴露本地列表或读取 API，发送端固定选中记录版本与文件快照，回收与导出操作不得改变传输内容。
4. **入库与重试**　接收方逐项验证字节数和哈希，使用自己的 UUID 文件名，在已有 staging 规则下发布。状态为待接受、发送中、校验中、成功、部分成功、拒绝、取消、失败或超时。成功仅在对端持久化回执后显示。回执按发送身份、任务 ID、项目 ID 持久化并用于查状态，防止 ACK 丢失导致重复入库。接收中断清理未完成项，已成功项保留，重试只重发失败项。首版以文件为重试单位。建议初始配额单文件 1 GiB、每批 2 GiB/20 项、每设备 1 个接收任务、等待接受 120 s、传输空闲 30 s，具体值由真实两机压测调整。检查可用空间并在流式写入过程中强制上限，拒绝路径分隔符、保留设备名、空字节与伪造长度，内容始终按本地 ID 入库。
5. **系统差异**　Windows 优先测试专用网络配置文件及公司防火墙策略，规则限定程序、端口和本地子网，公共网络默认停止接收。网络组策略不允许时说明原因。macOS 另验局域网隐私授权、Bonjour 和签名包，按所选发现 API 配置声明。Linux 另验防火墙、mDNS 运行环境、托盘与 Wayland 全局快捷键 portal。后两平台作为独立发布门槛。 [Windows 防火墙](https://learn.microsoft.com/en-us/windows/security/operating-system-security/network-security/windows-firewall/rules) · [Apple 局域网隐私](https://developer.apple.com/documentation/technotes/tn3179-understanding-local-network-privacy) · [Electron 全局快捷键](https://www.electronjs.org/docs/latest/api/global-shortcut)

#### M2a · TLS 双机探针

探针以手动 IPv4 和预先核对的公开证书复现双向认证。监听端仅提供 `GET /v1/probe` 的空 204 响应。每端用对端完整 SHA-256 指纹确认公开证书，TLS 握手校验证书链，应用校验确切指纹。锁定的 Electron 拒绝直接信任自签叶证书，探针用 OpenSSL 签发两天有效、可作为信任锚的证书。由该锚签发但指纹不同的证书仍被拒绝。应用身份生成方式和 `safeStorage` 持久化留在正式配对批次。 [Electron TLS 运行时说明](https://www.electronjs.org/docs/latest/api/environment-variables#electron_run_as_node)

两台 Windows 电脑在各自项目根目录执行以下命令。测试需 OpenSSL 3，可用 `XIGRA_TEST_OPENSSL` 指向可执行文件。示例使用 Git for Windows 自带的原生 OpenSSL。

```powershell
$env:XIGRA_TEST_OPENSSL = 'C:/Program Files/Git/mingw64/bin/openssl.exe'
$probe = '.\scripts\xigra-lan-tls.cjs'
$identity = Join-Path $env:TEMP ('xigra-tls-' + [guid]::NewGuid())
node $probe identity $identity
```

两端只交换 `public.pem`，并通过可信独立渠道核对打印出的完整指纹。各自在同一终端设定对端公开证书和指纹。选择 Windows 网络配置为「专用」的私网 IPv4，接收端和发送端填相同的接收地址。

```powershell
$peerCert = Read-Host '对端 public.pem 路径'
$peerFingerprint = Read-Host '已核对的对端完整 SHA-256 指纹'
$receiverIp = Read-Host '接收端私网 IPv4'
# 接收端
node $probe listen $identity $peerCert $peerFingerprint $receiverIp 43126
# 发送端在自己的终端执行
node $probe probe $identity $peerCert $peerFingerprint $receiverIp 43126
```

记录两方向的 TLS 版本和状态。复核指纹不匹配在连接前被拒，替换为第三方测试身份也无法得到 204。若公司防火墙或设备隔离拦截，记录现场状态。测试结束在接收端按 Ctrl+C，删除各自的临时身份目录。探针不修改防火墙配置。

本机自动验收使用 `node --test tests/xigra-lan-tls.test.cjs`，覆盖互信连接、缺少或替换证书、指纹不匹配、明文请求及业务路径不可访问。双机通过后继续设备发现、短时配对、持久身份与撤销，再接文字授权及落盘回执。

#### M2a · Arasn 逐条发送文字便签

在同一私网的两台 Windows 电脑上启动当前源码构建，进入工作区的「传送」并各自开启局域网。选中连接该网络的私有 IPv4。发现受限时可继续交换配对信息，其中已包含手动地址和端口。

1. 两端各自展开「设备配对与撤销」，生成并复制本机配对信息。通过可信渠道交换配对信息，并另行核对对端完整 SHA-256 指纹。两端都保存对方的配对。配对信息有效两分钟，设备身份和配对信任由系统安全存储加密保存。
2. 发送方打开一条已保存的便签，从「⋯ → 发送到局域网设备」选择设备。接收方可从便签小窗的「收件」或工作区的「传送」打开请求，只看到设备名、便签类型和字节数。接收方确认后才上传正文；成功以接收方 SQLite 落盘为准。
3. 复核双向发送、拒收、对端离线后重试、撤销后不可发送。重试使用原任务 ID，落盘回执和便签在同一 SQLite 事务写入。发送任务和收件提示保留在当前运行会话中，已接收便签与去重回执跨重启保留。

便签传送与旧整页共享互斥，避免新收件随当前工作页被共享。当前已通过同机双 Electron 实例的配对、确认接收和回执测试，本机私有网卡双向 mDNS 发现，以及独立 SQLite 进程的拒收、鉴权、回执丢失及重启去重测试。两台物理机上的 mDNS、防火墙及原生通知仍待现场验收。 [桌面验收](../tests/lan-notes-desktop.cjs) · [传输回归](../tests/lan-notes.test.cjs)

## 5. 重构评估

| 处置 | 模块 | 理由、成本与风险 |
| --- | --- | --- |
| 保留 | Electron、React、preload、安装包、原用户数据目录、SQLite Worker、文件对象库、RecoveryService | 这些能力已有实现和部分实机证据。保留可减少重写与升级风险。安全更新和新包回归继续执行 |
| 修改 | `desktop/main.cjs`、`WindowManager`、`QuickPanel` | 把分散的 show/hide、聚焦及尺寸决策汇入窗口模块，小窗默认只聚焦速记。中等成本，主要风险在焦点、输入法、重复呼出与多屏 |
| 修改 | `BoardClient`、`PanelEngine`、存储 schema | 增加本机记录接口和时间查询，旧白板保持兼容，使用同一事务和事件。中等成本，主要风险在操作顺序、迁移及恢复。优先写升级回归用例 |
| 修改 | `FileStation`、`FileEngine`、`ThumbnailService` | 保留文件生命周期，引入列表排序、任务状态、预览/打开与导出副本。中等成本，重点核验空间不足、取消、原件不变和解码资源 |
| 从主流程移出 | 绘图、富格式、旧网页共享 | 绘图与富格式进本地兼容画布。新版发布前关闭对外白板监听入口并保留旧代码用于过渡验证。迁移只在本地完成，避免旧 HTTP 快照暴露新增记录。正式移除旧网络代码前确认使用方、兼容策略与退路 |
| 新增 | `NoteService` 薄适配、`PreviewService`、发现与 `TransferService` | 小步加入，复用 SQLite 与对象库。M2 成本最高，身份、证书、网卡和网络异常都要求实机测试。文件预览按格式逐项验收 |

实施依赖顺序为 **保存确认与数据迁移 → 小窗收敛与文件取用 → 发现和授权 → 文字与文件传输 → 扩展预览**。每批保留可运行安装包与变更前的数据样本，发布前用真实旧数据副本演练。方案确认时优先确定默认布局、旧网页共享退场范围，以及 Windows 首发范围。

| M1 全局快捷键、托盘 | 在外部文本编辑器和资源管理器分别执行物理热键 30 次，输入焦点正确，无双开或闪现。占用新键时提示冲突且旧键可用。关闭转托盘，退出托盘才终止。连续重复键、Alt+Tab、中文组合输入均能继续操作 |
