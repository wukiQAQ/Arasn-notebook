# Arasn 拓扑空间工作台

## 现状与兼容方案

- 原工作页用 1600 × 1000 固定坐标存文字和笔迹。文字便笺同时出现在便笺列表，拖动和绘制依赖该坐标系。保留这一入口、导出、绘图和旧数据。
- `BoardClient` 按项目 ID 提交完整值，通过 `expected` 防止覆盖，按 `opId` 幂等重试。主进程恢复队列跨随机 HTTP 端口保存，SQLite 通过原事务写入项目与快照。新增节点沿用这条路径，现有库无需重写。
- 兼容方向为旧库到新版。写入新节点后，旧版程序无法解析新增项目类型。回退旧版时使用升级前的备份。
- 局域网工作页用共享口令读取快照和写入同一存储，无细粒度身份权限。第一批将新节点和布局从共享快照剔除，共享接口拒绝对本地节点的写入。访客仍可编辑旧便笺正文，服务端保留本地布局。设备配对便笺传送是另一入口，继续沿用其原权限。
- 文件库负责导入、哈希去重、回收和预览。第三批使用管理副本及文件引用表，节点存引用 ID，不持久化源路径、预览 URL 或二进制。

## 信息架构与设计

主要用户是在桌面整理想法、问题和待办的人。第一优先是找回空间位置并直接操作节点，其次是编辑正文和类型。笔迹、原画布导出、局域网分享仍从工作页进入。

| 方向 | 布局和取舍 |
| --- | --- |
| 制图工作台（采用） | 画布占主要空间，顶栏少量分组控件，底部小地图；选中后才出现详情。低对比网点提供移动参照，留出以后放连线的空间。 |
| 白板工具轨 | 把创建、连线、绘图集中到竖排工具轨，便于密集操作，但第一批容易增加模式切换成本。 |
| 节点检查器 | 节点列表和详情常驻左右两列，查找快，留给自由摆放的区域较窄。 |

采用现有主题的 `--xigra-window`、`--xigra-surface`、`--xigra-text`、`--xigra-muted`、`--xigra-border`、`--xigra-selected` 以及同一字体。14px 正文、12px 元信息、8/12/16px 内间距。节点用边框、标题和类型文字建立层级。玻璃质感集中在小地图等悬浮控件。新节点只播放一次轻微淡入与位移，减少动态效果时取消。窄窗详情覆盖画布局部，可独立滚动。

## 数据和交互

- `text` 沿用原有 `id/x/y/text`，可选 `topology` 记录独立布局。读取老数据时由 `x/y` 生成默认布局。编辑正文保留原 ID，移动不改纸面坐标。
- 新项目为 `{ type: 'node', text, topology }`。项目 ID 仍由 BoardClient 生成。`topology` 持久化 `{ x, y, width, height, kind, status, hidden? }`。五种类型与处理状态独立。第一行作标题，后续为摘要。移出拓扑用可恢复的 `hidden`，兼容存储的硬删除墓碑规则。
- 视口保存 `{ roomId, x, y, zoom }`，其中 `x/y` 是视口中心的世界坐标。变换为 `screen = size/2 + (world - center) × zoom`。支持负坐标，持久化限 ±1,000,000，缩放 25%–200%。空白拖动平移，滚轮以指针为锚缩放，按钮和小地图支持直接导航。创建、移动、类型、状态和移除可撤销/重做。撤销验证当前布局，合并时保留当前正文。详情文本框使用原生文本撤销。
- 第二批新增独立 `edge` 项目 `{ from, to, relation, label? }`。端点必须存在且不可自连，边 ID 独立。软删除节点时暂停渲染关联边，恢复后自动显示。跨项目变更用同一动作历史，验证当前版本后提交；需要原子性的批量编辑应补充事务。
- 第三批讨论采用独立 `reply` 项目 `{ nodeId, authorId, body, createdAt }`。讨论记录可追加，系统处理事件可用独立事件类型记录。节点附件引用在文件库中使用 `nodeId` 区分归属；导入和引用失败可分别重试，移除引用保留管理副本。
- 第四批先做能力协商和主机/查看/编辑权限；沿用版本号、幂等 ID 和本地恢复队列，冲突并列保留，不自动覆盖。附件通过受权传输与校验后重建本机引用。测量现有快照成本后再决定是否增加按修订增量拉取。首批仅渲染视口附近节点，保存只在拖动结束时提交，地图用 SVG 聚合轮廓。
