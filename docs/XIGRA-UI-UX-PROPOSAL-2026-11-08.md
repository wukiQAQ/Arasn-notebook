# XIGRA｜隙格 · 桌面体验设计提案

> 让每个瞬间，都有归处

评审基线为仓库中的轻泊 0.6.0。首轮按 Windows x64 桌面体验设计，尺寸均为内容区 DIP。提案中的模式、状态与尺寸是待验证的设计，当前能力依据源码和已有截图区分。

## 1. 现状审计

小窗已经有全局快捷键、托盘、自动保存与文件拖入，可以作为重设计的底座。最需要改变的是首屏任务顺序。呼出时用户应该先看到能输入的位置，其次才是记录列表、文件入口和编辑选项。

| 优先级 | 已看到的问题 | 对任务的影响 | 建议 |
| --- | --- | --- | --- |
| P0 | 小窗底部「传递／共享」进入局域网白板共享。现有服务共享文字与笔迹，文件保留在本机 | 容易把共享链接误读成向某台设备发送某个文件 | 旧功能明确叫「旧白板共享」。独立定义逐项发送，等设备发现、接收授权和回执可用再开放入口 |
| P1 | 520×640 小窗中，模式栏、便笺选择行、文字颜色／字号／粗体占据正文前的三个层次 | 上方界面抢走正文焦点。短句输入的认知成本接近打开一个编辑器 | 合并为一条模式行，正文在其下直接开始。记录管理与格式分别放入「最近」和上下文菜单 |
| P1 | 文件抽屉首屏同时出现导入、粘贴、清空、多个视图、筛选、分页和恢复。空列表依然显示分页 | 第一次拖入的目标弱，维护操作与高频动作视觉权重接近 | 空状态直接给「拖入文件」与「选择文件」。有内容才显示列表与筛选。清空、回收站、备份移入文件管理 |
| P1 | 缩略图存在，但卡片动作与文件详情没有形成明确的浏览路径 | 用户容易把缩略图当成已支持完整预览，也难快速判断取用方式 | 用「列表 → 详情」统一文件路径。受支持类型预览，其余显示名称、大小、类型及可用的取用动作 |
| P1 | 展开页以画布、工具轨、浮动绘图条为中心，文件另在抽屉；小窗以打字、画图、文件为顶栏 | 展开后需要重新找同一条记录或文件 | 两种窗口共用「记录／文件／传输」。展开只增加列表或详情所在列。旧画布保留在更多菜单 |
| P1 | 主进程会聚焦窗口并通知渲染器。小窗正文默认取当前选择或列表末项 | 现有焦点策略适合继续编辑，快速捕捉时则可能误写已有记录 | 新一轮呼出默认给新草稿，未提交内容优先恢复。主动选择继续上次操作后才还原该区域 |
| P2 | 莓灰旧品牌、底部提示文案、各块描边同时出现。展开画布有很大空区，常用动作分布于上下和侧边 | 看得出各模块，整体节奏和品牌识别仍弱 | 用松绿品牌标记与固定对齐线统一两种窗口。常驻状态集中到底栏，分隔线只出现在真正的区域边界 |

## 2. 品牌视觉方向

**Moment 是落点，Grid 是秩序。** 呼出后，光标、空投递区或选中条目应当立刻可见。不同内容放入相同的网格，每项都有稳定的标题、类型、状态与动作位置。规则网格体现在边缘对齐和行距中，正文背景保持平整。

- **品牌符号**采用两块错开的直角单元，中间保留一个「隙」。先在 16、24、32px 检查轮廓，小图标在单色下也能辨认。字标用 `XIGRA` 配「隙格」，标语用于首次空页与关于。
- **层级**由大面积冰白与正文建立。松绿用于主动作和品牌，薄荷用于选中或可达状态，保存成功保持低对比视觉权重和清楚文字。传输失败使用独立语义色。
- **产品用语**统一使用「记录」「文件」「传输」作为模式，「存入」「打开」「发送」「收起」作为动作。状态区分「已保存」「等待接收」「已送达」，每个词对应一个可验证事件。

## 3. 两套改版方案

| | A · 单元舱 | B · 时间格 |
| --- | --- | --- |
| 首屏重心 | 默认进入单栏记录，光标落在新草稿。模式切换时同一块内容区换内容 | 顶部保留一段固定速记入口，下方按时间混排记录、存入文件与传输结果。模式栏用于筛选活动 |
| 紧凑形态 | 一块主内容区和一条最近入口。文件选中后在同一区域进入详情 | 速记入口与活动列表共享首屏，时间列与内容列对齐。点条目进入详情 |
| 展开形态 | 同窗双栏，左边当前模式列表，右边编辑、预览或任务详情 | 左边跨类型时间线，右边选中条目或任务详情。分日折叠和类型过滤是主要导航 |
| 视觉区分 | 大留白、松绿字标、薄荷短线或浅底表示选中，列表密度低 | 更强的日期和时间刻度，类型符号帮助扫读，点状状态沿一条纵向基线排列 |
| 最合适的任务 | 快速写一句、放入文件、选定内容发送 | 回找「刚才做过什么」、追踪一组记录与文件、检查近期任务 |
| 取舍 | 跨类型历史需要「最近」入口，新增活动容易被低调收起 | 时间信息占宽度，空白编辑面积较小。后台任务更新可能打断扫读，需要保持滚动锚点和稳定排序 |

## 4. 推荐单元舱

首发采用 **A · 单元舱**。它把每次呼出的首屏交给一个明确任务，最小窗口也能先输入、拖入或查看当前选择。记录、文件和传输共用外壳，但各自保留清晰状态。借用 B 的时间标签放进「最近」与传输任务，保留回找价值。

后续评审用相同的 400×460 线框比较四项任务。输入一句并收起、找回上一条、拖入后取用、把已选文件发给指定设备。记录能否不读提示完成、焦点是否正确、有没有选错对象，以及空状态下第一动作是否明确。当前推荐依据任务结构与界面审计，尚未做用户测试。

## 5. 紧凑悬浮模式

建议默认 **480×560**，保留 **400×460** 的最小窗口校验点。横向内边距 16，内容用单栏。标题行约 48，模式行 44，状态栏 32。剩余空间先给输入或列表，最近内容只使用一行入口，窗口足够高时可展示最多两条摘要。短窗口先收起摘要，正文保持原字号。

```text
┌────────────────────────────────────────┐
│ ▦ XIGRA 隙格                   展开 · 收起 │
│  记录           文件           传输        │
│                                        │
│  开始记录…                              │
│  ｜                                    │
│                                        │
│  最近记录  ›                       更多  │
│  ● 本机记录                传输未启用     │
└────────────────────────────────────────┘
```

| 区域 | 设计行为 |
| --- | --- |
| 顶部 | 品牌固定在左。右侧保留展开与收起，设置移入更多；图标需有可访问名称和悬停提示。系统窗控策略沿用当前应用，实机核验标题栏、拖窗热区与焦点 |
| 记录 | 呼出即进入可输入草稿。输入提示占一行。最近入口打开列表，支持搜索、选择和新建。已有记录的发送、复制、格式和删除放在上下文菜单。纯文本是首发主路径，旧样式由兼容视图保留 |
| 文件 | 空态显示可拖入区域和「选择文件」。有内容时改为 48–56 DIP 列表行，左缩略图或类型图标，中间文件名与大小／类型，右侧更多。打开详情复用主内容区，返回列表保留滚动、筛选和选择 |
| 传输 | 默认显示是否启用、设备或当前任务。选中条目的发送进入目标选择与确认。当前任务与接收请求优先显示，历史任务折叠。首发本地版中，用明确未开放说明取代看似可用的发送控件 |
| 底栏 | 左侧显示本地写入状态，右侧显示传输状态。错误以文字和图标呈现，点状态可查看具体失败项目与恢复操作。任务进度在所属内容区显示 |

窗内拖入文件使用统一投递反馈。仅在拖入受支持的文件时出现覆盖式「松开存入」提示。拖入记录页也能收下文件，完成后显示「已存入 1 项 · 查看」，不强制跳走并打断正在输入的记录。文件长名省略且可在详情和键盘提示读全。每个模式只有一个主滚动容器。

## 6. 展开工作模式

建议默认 **1120×760**。同一窗口、同一模式和条目，展开时保留当前草稿、所选内容、筛选和详情的滚动位置。宽度达到 900 时，内容为约 280 DIP 列表和弹性详情。720–899 使用列表与详情的单栏切换。宽屏优先增加正文和预览可用宽度，避免无意义的空列。

```text
┌──────────────────────────────────────────────────────────────────┐
│ ▦ XIGRA 隙格        记录    文件    传输               收回 · 更多 │
├───────────────────┬──────────────────────────────────────────────┤
│ 搜索当前模式   ＋  │ 当前内容                                    │
│                   │                                              │
│ 选中行             │ 正文编辑 / 文件预览 / 传输任务                │
│ 其他条目           │                                              │
│                   │ 选中后出现相关动作                          │
├───────────────────┴──────────────────────────────────────────────┤
│ 已保存                                    连接 / 活动任务状态     │
└──────────────────────────────────────────────────────────────────┘
```

| 模式 | 列表区 | 内容区 |
| --- | --- | --- |
| 记录 | 最近修改、搜索、新建，显示首行和可信时间。旧记录无可信时间时显示为空 | 记录正文为主，最大阅读宽约 680 DIP。顶部显示上下文和复制／发送。多选或删除需要明确选中 |
| 文件 | 名称搜索、类型筛选、选择文件；列表为默认，展开后可切换图片网格 | 图片详情或类型信息，支持按能力显示打开、导出、发送。不可预览时给出可用出口，批量动作仅在有选中项时出现 |
| 传输 | 设备与任务分组，待处理接收请求置顶 | 显示对象、来源或目标、进度、当前状态及恢复操作；点击历史查看回执。任务在收起窗口后继续，进度从真实任务事件更新 |

窗口之间的过渡采用列的显隐与内容重排。常用目标保持同一位置语义。设置、回收站和旧画布从更多菜单进入，回到当前模式时恢复原工作上下文。

## 7. 设计系统草案

| 语义 | 浅色 | 暗色 |
| --- | --- | --- |
| 窗口背景 | 冰白 `#F3F7F5` | 深松 `#11231D` |
| 编辑／浮层表面 | `#FFFFFF` | `#1A2E26` |
| 正文 | `#142821` | `#E5F2ED` |
| 次级文本 | `#48625A` | `#ABC4BB` |
| 品牌／主按钮 | `#184438`，字 `#FFFFFF` | `#A6E1CB`，字 `#091E17` |
| 选中底／字 | `#DBF2E8` / `#16352C` | `#28473A` / `#C6F0E0` |
| 分隔线 | `#D6E3DE` | `#355247` |
| 焦点／可达图标 | `#237356` | `#A6E1CB` |
| 错误底／字 | `#FCEEF0` / `#A1313D` | `#42262B` / `#FFC1C9` |

- **字体**用 Segoe UI 与 Microsoft YaHei UI 系统栈。应用名称 16/22 半粗，详情标题 18/26 半粗，输入正文 16/24，控件与列表 14/20，元数据 12/18。进度数字用等宽数字特性。正文小窗保持 16，列表先截断文件名，不缩字号。
- **网格**以 4 DIP 为单位，间距使用 4、8、12、16、24、32。列表左边缘、编辑区和状态栏共用对齐线。普通主控件命中区至少 40×40，模式切换及主动作优先 44；小图标用透明点击区扩展。
- **形状**控件圆角 6，列表选区与局部面板 8–10，窗口内容外壳 12–14。1 DIP 分隔线用于区域边界。常驻内容用平面层级，只有浮层用一档低透明度阴影，例如 `0 12px 32px #102C2220`。
- **图标**使用 20×20 网格与约 1.6 线宽。记录为开口纸面，文件为带托盘的格，传输用相邻格间的单向箭头。只定制品牌与三个模式，其余优先复用现有 Lucide。状态点同时配文字，不靠绿色表示成功或连接。
- **交互态**悬停轻染表面，按下加深，选中为薄荷底加文字或标记。键盘焦点用 2 DIP 轮廓及间隔，与选中独立。禁用不响应并在相邻位置说明原因。错误贴近相关内容，保留用户输入及恢复动作。加载保留容器尺寸，进度只显示可信值。
- **动效**模式切换用 100–140 ms 的淡入或选中条移动；详情与抽屉用约 150 ms 的位移和淡入。键盘呼出与收起不等待动画，焦点先可用。拖放反馈即时，无循环。减少动态效果时切换即时生效，状态仍可读。

计算样本中，浅色主按钮白字约 10.92∶1，次级文字／冰白约 6.13∶1，焦点绿／冰白约 5.31∶1，暗色次级文字／背景约 8.85∶1。这些是色值样本，实际控件、组合状态与读屏还需验收。

## 8. 核心交互与恢复

| 流程 | 默认／空态 | 悬停／选择 | 处理中／完成 | 失败／恢复 |
| --- | --- | --- | --- | --- |
| 呼出 | 常驻后全局热键唤起。默认聚焦新草稿，待恢复内容优先。可设置继续上次模式 | 展开、收起和更多显示提示。键盘焦点落在正文或恢复的主区域 | 窗口已显示但存储未就绪时仍可输入内存草稿，并显示「正在准备」；可写时提交 | 热键冲突保留旧配置，托盘仍可打开。窗口位置越界时回到可见工作区；系统焦点和输入法需要实机核验 |
| 记录 | 空草稿仅展示输入提示，首次有效输入才创建记录。最近列表空时提示可直接输入 | 点击记录或键盘选择后显示选中，草稿切换前保留未提交内容 | `编辑中 → 保存中 → 已保存`，数据库确认后才显示已保存。恢复旧样式时编辑与保存使用同一记录 ID | 失败保留草稿并提供「重试」「复制文本」。版本冲突可查看当前与草稿，允许另存，避免覆盖其他版本 |
| 拖入 | 空态可以拖入或选择文件，有内容时仍保留导入入口 | 有效文件进入窗内时显示「松开存入」，拖离即清除。多项导入按批显示 | 实际复制进度由服务上报；成功后更新列表，部分失败显示成功数与失败数 | 按条提示空间不足、源文件变化或不可读，支持重试失败项。取消按服务能力启用，原件保留 |
| 查阅与取用 | 最近存入优先，搜索无结果提供清除筛选；无文件状态展示导入动作 | 列表行与多选有独立标记；从详情返回保持选择及滚动 | 预览加载保留位置。建议先开放 PNG/JPEG 详情，系统打开使用可管理副本，导出明确目标位置 | 不支持或解析失败时展示文件类型、大小及可用打开／导出动作。风险类型只给显式导出，预览回退不影响原文件 |
| 局域网发送 | 已选记录或文件进入发送，展示对象清单。无设备可扫描或输入地址，首次配对核对短码 | 设备名、配对状态与可达性独立显示，选目标后明确确认。接收方看到来源、条目数和大小后接受或拒绝 | `等待接受 → 发送中 → 等待确认 → 已送达`。进度取实际字节，接收方校验并落盘后回执。收起后任务继续 | 区分离线、拒收、超时、校验失败。允许取消或重试失败项。丢回执先查任务状态，依任务 ID 去重；半成品不进列表 |
| 收起与继续 | 同一快捷键或收起按钮回到原工作；Esc 先处理输入法候选与已打开浮层 | 收起按钮有可识别焦点，键盘能从详情返回列表 | 隐藏前请求提交或写入恢复队列，窗口不等待网络。重新呼出恢复待处理状态 | 隐藏期间保存失败，下次呼出提示恢复，保留可复制的草稿。正常退出遇到尚未持久化内容时提供明确处置 |

在文件详情提供「发送」和在传输页查看任务是同一流程。前者携带已经选好的条目，后者呈现设备、请求和任务状态。设备发现只产生候选，配对和逐次接收确认是内容授权。现有白板共享路径及其退场策略需单独决定。 [既有产品与协议规划](QUICK-WORKSPACE-PLAN-2026-11-08.md)

## 9. 前端实施建议

继续使用仓库的 Electron、React、TypeScript、Base UI 与 Lucide。先接入现有本地数据和桥接能力，样式和数据协议分阶段迁移。

| 层 | 拆分与职责 |
| --- | --- |
| 外壳 | `WorkspaceShell`、`WindowBar`、`ModeTabs`、`StatusBar`、`DropOverlay`。紧凑和展开共享一棵模式组件树，按容器宽度重排。设置与系统窗控仍走既有入口 |
| 记录 | `RecordEditor`、`RecordList`、`RecentEntry`、`RecordActions`。编辑器持有草稿和焦点，记录模型继续从现有便笺读取，提交确认后更新列表。时间元数据升级独立验证 |
| 文件 | `FileList`、`FileDetail`、`ImportFeedback`、`SelectionActions`。先把现有 `FileStation` 的导入与恢复接到新 UI。使用文件 ID 查询，不在渲染器保存大文件正文 |
| 传输 | `DevicePicker`、`ReceivePrompt`、`TransferQueue`、`TransferDetail`。只有对应后端能力存在时注册操作。进度、取消和送达以主进程任务事件为准 |
| 状态与样式 | Window 状态保存大小、模式、焦点目标和条目 ID。持久化数据来自 `BoardClient`／IPC，草稿、列表筛选和浮层在各自模块管理。跨模式任务使用有类型的状态机。CSS 变量统一表面、文字、控件和动效，按组件语义用 token，避免给每块界面独立配色 |

隐藏保持窗口和编辑状态。展开不重建草稿。前端不复制已保存记录为另一套可写缓存，主进程与 Worker 继续承担权限、文件流、事务和恢复。现有 Chromium 测试可验证视口、键盘与状态；真实热键、系统焦点、窗口行为和 LAN 必须单独用打包应用验证。 [当前依赖](../package.json) · [预加载接口](../desktop/preload.cjs) · [现有 BoardClient](../src/board.ts)

## 10. 分阶段实施与放行条件

| 阶段 | 内容 | 放行条件 |
| --- | --- | --- |
| 0 · 评审 | 选定方向、绘制实尺寸设计稿、确认旧白板共享出口和首次发布范围 | 两种尺寸和三个模式都有任务路径、空态和失败态。设计稿标清真实与规划能力 |
| 1 · 小窗记录 | 品牌、外壳、默认聚焦、新草稿、最近记录、主题与收起恢复 | 400×460、480×560 无遮挡。真实热键、中文输入法、选择与焦点、保存失败和重启恢复通过。确认前后数据可读 |
| 2 · 文件与展开 | 共用文件列表、投递、取用与预览；两种窗体共享上下文，兼容旧画布 | 大文件进度与批量失败清楚，源文件完整，重启可找回。720/900/1120/1440 检查布局与焦点，PNG/JPEG 和不支持格式回退可用 |
| 3 · 传输 | 先做发现／地址回退、配对、文字收件，再做文件流、接收授权与回执 | 两台电脑实测拒收、断网、重试、校验、重复回执。旧共享与新传输边界清楚。可关闭功能并继续本地使用 |
| 4 · 发布 | 实机多屏/DPI、长时间驻留、安装升级与回归；更新用户可见品牌 | 在 100%、125%、150% 等缩放点检查裁切与焦点。用实际包对比呼出到可输入的 P50/P95 和空闲占用，确认验收阈值。保留旧数据、安装与迁移验收记录 |
