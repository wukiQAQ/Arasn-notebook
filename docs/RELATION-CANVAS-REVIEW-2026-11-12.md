# 关系画布：现状审查与四阶段实施方案

审查日期：2026-11-12。本轮为代码与数据审查，尚未实施页面切换、运行用户库迁移或做新的截图验收。此前已确认的引用模型继续沿用；本文把现有基础与本次四阶段目标对齐，待用户确认本次实施范围后优先完成第一阶段。

## 1. 架构分析：可复用基础与真实差距

| 模块 | 当前代码事实 | 本次处理 |
| --- | --- | --- |
| 白板 | `TextValue` 保存正文及纸面 x/y；`StrokeValue` 保存笔画。通过 BoardClient、expected/version/opId、恢复队列和 SQLite 保存 | 保留原 ID、纸面坐标和保存语义；不把笔画自动转为内容节点 |
| 速记 | `records/session.ts` 只列出、打开和编辑 text；与白板 text 共用正文 | 统一读取 text 与兼容旧 node，添加到画布只创建引用，打开原记录不复制正文 |
| 当前画布 | TopologyWorkspace 读取所有 text/node；新建写独立 node；布局写旧 topology。已有平移、缩放、小地图、移除恢复、布局撤销和详情编辑 | 切到 canvas-node.layout，正文按 contentRef 实时解析；切换后冻结旧 topology，禁止双写 |
| 节点展示 | 已有首行标题、后续摘要、类型与状态；五类为便签/问题/灵感/待办/文件 | 保留可读卡片；补充讨论类型、真实时间和附件数；已有灵感保持兼容 |
| 导航 | 已显示“关系画布”，使用 PanelsTopLeft；共享为 Radio，传送为 MonitorUp | 延续名称，阶段一将画布图标细化为两张内容卡片与连接曲线，保持 1.65 线宽及选中态 |
| 文件 | FileStation 经 preload/文件服务访问 SQLite 元信息及受管文件；FileMedia 为私有组件，仅图片缩略图可预览 | 提取共享预览；按稳定文件 ID 获取，不以文件名匹配，不把通用文件都宣称可预览 |
| 引用基础 | 已有 canvas-node、canvas-edge、content-link、resolveContent/nodesForContent/relatedContent | 直接扩展，避免新建第二套业务数据库 |
| 迁移 | 已有显式 dry-run、备份、事务、确定性节点 ID、版本 2 保护及恢复队列门槛 | UI 完成单一路径切换后才开放入口；先预览再显式执行，不后台自动迁移 |
| 文件保护 | 已有 canvas_file_refs owner 索引及清理保护 | 文件节点与 owner 引用必须同事务保存，移除画布引用不回收文件 |
| 连线 | 只有底层类型及校验；没有建边、曲线渲染、选择或删除 UI；缺少独立关系类型 | 阶段二增加交互和 relationType，不能把现有 label 当作完整能力 |

当前并不是服务器/设备拓扑实现，不需要引入网络诊断概念。主要差距是内容引用尚未接入实际页面，而非缺少画布坐标算法。

## 2. 数据模型建议

沿用现有 Item 容器中的稳定 id/version，内容与布局分别拥有版本：

```text
原始内容：text 或兼容旧 node / files
    ↑ contentRef { kind: record | file, id: 原始对象 ID }
canvas-node：roomId + canvasId + contentRef + layout
    ↑ fromNodeId / toNodeId
canvas-edge：roomId + canvasId + relationType + label + direction
content-link：roomId + recordId + targetRef（附件或正文层的关联）
```

| 要求 | 保存位置与规则 |
| --- | --- |
| 稳定 ID | 使用既有 Item key；迁移沿用确定性引用 ID；新建分配内容 ID 和节点 ID |
| 类型、位置、尺寸 | layout.kind/x/y/width/height；保留旧 idea，新增 discussion；服务端校验同步扩展 |
| 标题、摘要 | 从原始正文派生，首行标题、后续 1–3 行摘要；文件标题来自文件元信息；不持久化重复正文 |
| 状态 | 阶段一沿用 layout.status 作为该节点的组织状态；问题显示“待处理/进行中/已解决”；全局任务状态须以后独立进入内容模型，不能暗中让多个画布共享布局状态 |
| 关联对象 ID | contentRef；解析不到原对象时保留引用并明确显示已删除/丢失 |
| 附件 | 经 content-link 与文件元信息解析；不复制文件字节；无真实附件显示 0，不生成占位附件 |
| 创建、更新时间 | 新内容、节点、边由存储端记录真实时间；正文更新时间和布局更新时间分别处理。文件已有 created_at，但当前前端类型未暴露，需补齐 |
| 历史时间 | 旧 Item 没有创建/更新时间，不能由 version 推断；显示“历史时间未知”，迁移时间仅记为迁移时间 |
| 连线类型 | relationType = related/reference/dependency/resolves/source/attachment；中文为关联/引用/依赖/解决/来源/附件。旧边缺省 related，保留 label 作为可选说明 |
| 移除与删除 | 节点移除只更新 hidden；原内容不变；隐藏端点对应边暂停绘制，恢复节点后重新显示。删除边只删除边对象 |

必须注意：当前服务端按白名单重建值，单独给 TS 类型加时间、讨论或 relationType 会被过滤或拒绝。存储、校验、恢复、迁移、备份恢复都必须同步覆盖。

“附件”关系线只表达画布关系；真正记录附件仍由 content-link 管理，不能因画一条线就悄悄修改原记录附件。

## 3. 兼容实施边界

1. 不重新讨论已定引用方向：正文保留原 ID，canvas-node 不保存副本，旧 node 保留为兼容内容源。
2. 默认 canvasId=roomId。已有 text 的派生位置和 hidden 状态全部迁移；升级不隐藏用户原先可见的内容。
3. 新 UI 一次切到引用布局；旧 text.topology/node.topology 只作为兼容证据，不再可写。未迁移库展示明确升级入口，不允许旧页继续写入新布局。
4. 新建画布内容采用 localOnly text + canvas-node 的原子命令：校验、正文、引用、回执同事务提交，失败全回滚，重试复用原操作 ID。当前逐次 BoardClient.edit 不能充当原子事务。
5. 已有速记加入画布按 roomId/canvasId/contentRef 去重；已在画布则定位，已移除则恢复。不要把软移除当作原文删除。
6. 迁移前处理恢复队列、保存草稿并备份；预览绑定 revision，过期须重算。提交后旧程序不能直接降级可写，回退走迁移前完整备份。
7. 保持旧白板共享过滤；画布、文件引用与 localOnly 记录不通过旧共享 API 暴露。本次不改变已有公开 text 的共享范围。
8. 输入法组合期间禁止跨页；跨页保留原记录、光标、列表查询和画布相机。文件元信息刷新须覆盖重命名/回收/恢复与重新聚焦，禁止全库分页扫描定位文件。

## 4. 视觉方向与设计约束

用户是整理便签、问题和文件的现有工作台用户；主要任务是读懂内容、加入已有记录并理解关联。主要内容优先级为正文摘要，其次状态/类型，最后时间和附件数。

比较三个方向：

- **内容卡片画布（采用）**：中心自由画布、顶部紧凑工具条、选中后出现操作；Graphite Blue 卡片，深色点阵底。与现有便签一致，后续曲线关系有清晰空间。
- **关系清单 + 画布双栏**：左侧长期展示内容目录，适合大量检索，但占用当前工作台与窄窗空间；后续作为内容选择器考虑。
- **主题簇工作区**：主题容器与卡片分组，可读性好，但引入分组语义和额外布局规则，超出第一阶段。

紧凑设计 brief：沿用 Segoe UI / Microsoft YaHei UI、现有控件圆角和蓝色焦点；画布局部固定深色，不强制整个应用变暗。摘要与原记录同源，图标表达内容与连接，不使用服务器、地球或网口。

建议画布局部 token：底色 #151A22、点阵 #354052、卡片 #222A36、主字 #F1F3F7、次字 #B6C0D0、焦点/选中线 #80B4FF；以真实截图校准对比度。标题 14px/600、摘要 13px/20px、元信息 12px/18px；卡片宽 280–320px、高至少 160px，摘要三行截断；内边距 16px、间距 8px，卡片圆角沿用 11px。类型与状态使用文字和颜色双重提示。

第一阶段：头部拖动、正文区可读可选，双击打开原记录；空格按住拖动支持从节点上平移，输入框不拦截空格；Ctrl+滚轮以指针为中心缩放。移动中只更新渲染预览，松手一次提交布局，避免每个 pointermove 写库。失焦或 pointercancel 必须取消临时手势。

## 6. 分阶段计划与验收标准

### 第一阶段：完成可用画布与速记闭环

实施顺序：原子创建与兼容读取 → 引用布局切换及迁移入口 → 添加已有速记/查看关系/打开原文 → 深色画布与头部拖动、空格平移、Ctrl 缩放 → 桌面和窄窗验证。

验收：

1. 便签/问题/待办/文件引用形态可区分，讨论至少完成模型与清晰预留；第一阶段没有文件选择/预览入口时不把文字便签伪装成真实文件。
2. 卡片直接显示真实标题和 1–3 行摘要，状态文字可读；新记录时间真实，历史时间明确未知。
3. 双击空白新建、头部拖动、空格平移、Ctrl 滚轮缩放、双击打开原文、选中快捷操作正常；输入法和键盘焦点不回归。
4. 速记加入画布不复制正文，重复加入定位同一个节点；双向打开准确，改原文立即更新摘要。
5. 删除/恢复画布节点不删除/重建原记录；移动不修改纸面坐标或正文版本；重启后布局、移除状态和视图保留。
6. 原子创建故障注入无半条记录/悬空引用；迁移幂等，恢复队列和旧白板共享隔离验证通过。

第一阶段不把连线或文件预览列为已完成；本阶段交付后仍不代表全需求验收通过。

### 第二阶段：关系连线、详情与文件闭环

实施：节点锚点拖出平滑 SVG 贝塞尔曲线；较宽透明命中区域；选中高亮、关系类型与说明编辑、删除及撤销。沿用已有详情区，完善原内容入口和关系编辑。文件页按原文件 ID 添加节点，复用共享图片预览及导出能力，显示文件类型、名称和大小；不支持的格式明确提示。

验收：六类关系可创建/修改/选中/删除，非法自连和跨画布边被拒绝；拖动和缩放时端点稳定；隐藏/恢复节点后连线正确停显/重显；重启连线保留。文件引用不复制字节，图片能预览；非图片有明确入口/限制；重命名同步，丢失/回收/清理状态可辨，移除节点不误删文件，引用索引与备份恢复一致。

### 第三阶段：预览、讨论与快捷操作

实施：文件缩略图、加载/失败/重试状态、讨论内容与更新时间、快捷添加关联/打开来源、状态操作优化。根据实际元信息支持范围再扩展预览格式。

验收：缩略图失败不阻塞画布，缓存失效正确；讨论正文只有一份主数据；内容更新与布局变动时间不混淆；键盘可完成主要快捷操作；长标题、大摘要、多附件和缺失内容无溢出或假信息。

### 第四阶段：多选、批量关联与协作评估

实施：框选/修饰键选择、批量移动和关联；批量操作定义回滚或逐项结果。单独评估局域网权限、协议能力、版本冲突、断线恢复及附件传输，不把现有文字传送当作画布协作。

验收：多选不误拖动/误删正文；批量结果可追溯、失败可恢复；基于约定规模压测后给出实际性能；协作输出可实施方案及双端验证门槛，未经真实双机验证不宣称已支持协作。

完整八项验收映射：摘要→一；连线→二；速记加入→一；文件加入/预览→二；内容同步→一/二；节点删除安全→一/二；重启布局/连线→一/二；名称/图标→一。
