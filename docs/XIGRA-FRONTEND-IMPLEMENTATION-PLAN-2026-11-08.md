# XIGRA｜隙格 · 前端实施准备与验收计划

以「单元舱」为实施基线，优先紧凑小窗，首发按 Windows x64 评估。设计有条件通过，可先做 Tokens 与基础控件。画板迁移、保存语义、完整文件预览和新互传分别设置放行条件。本文的新增路径是拟议文件，阶段审批前不创建应用实现。

## 1. 设计验收

颜色、字号、间距、圆角、图标和主要状态都有草案。单栏小窗、同窗展开的规则足以做实尺寸稿。冰白留白、深松绿主动作、薄荷选中和统一对齐线符合轻量定位。实施前要把下面的状态和边界写入设计稿；字号与配色样本不能代替实际控件验收。

| 检查点 | 结论与缺口 | 调整及最迟完成点 |
| --- | --- | --- |
| Tokens 和组件 | 草案覆盖核心视觉角色。不同按钮层级、进度、警告和强制颜色模式仍缺组件级对照 | 第 1 批列出普通／主操作／危险按钮，以及禁用、悬停、按下、选中、焦点、错误。亮暗色各有对照。状态同时有文字，键盘焦点独立于选中 |
| 紧凑和展开 | 目标 480×560、最小 400×460；展开 1120×760，900 以下单栏。方案标的是内容区，现有 `BrowserWindow.setSize` 和最小值对应系统窗口大小 | 第 2 批区分渲染区测试与原生外框。按实际内容宽度切换布局。短窗口先收起最近摘要，底栏有优先级，主区保持单一滚动。第 7 批测 899/900 边界、系统标题栏和不同 DPI |
| 速记 | 新草稿、恢复优先和保留草稿方向明确。首次输入、空草稿、失败后收起及继续同一条仍需可执行规则 | 第 3 批约定空草稿不写记录，首次有效输入分配一次 ID，隐藏后未提交先恢复。无可靠时间时沿用现有列表顺序，不凭 UI 补历史时间。对照真实提交、冲突和恢复失败分别提示 |
| 画板 | 提案有兼容入口意图，缺新入口、返回行为与编辑能力清单 | 第 5 批前保留原画图入口。实尺寸稿增加「更多 → 画板」与命令入口，返回原模式及选中项。标注笔、形状、擦除、撤销、缩放、便笺拖动与 PNG 导出各自所在视图 |
| 文件 | 空态、列表和详情规则清楚。已有的 PNG/JPEG 缩略图与所需完整预览、系统打开是不同能力 | 第 4 批先接已有缩略图、类型信息、导出与恢复。完整预览、打开副本及其错误/加载状态需另审能力与权限。统一窗级文件拖放，文字粘贴留在输入框，明确唯一事件处理者 |
| 传输 | 逐次接收与回执流程完整，设备发现、配对和文件流依赖新服务 | 第 6 批确认协议与功能门禁。旧白板共享保持独立入口。区分未启用、未配对、离线、等待接收、等待确认、送达；发布时只启用真实支持的操作 |
| 全局操作 | 模式、详情、对话框和系统收起都有键盘路径，尚缺优先级矩阵 | 第 2 批约定输入法 → 最内层弹层 → 详情返回 → 收起。Tab 回焦点、Ctrl+K、全局热键、拖窗和系统菜单用真实窗口复查。Ctrl+Z 优先让文本输入处理，其余交给当前编辑视图 |

视觉方向和两套模式规则以现有提案为准。本轮没有新高保真稿或原生渲染，后续以经评审的实尺寸稿作为截图对照。 [设计提案](XIGRA-UI-UX-PROPOSAL-2026-11-08.md) · [轻泊实装证据](LAGOON-IMPLEMENTATION-2026-11-04.md)

## 2. 现有项目审查与前端范围

当前栈为 Electron 45.2.1、React 19、TypeScript、Vite、Base UI 和 Lucide。`App` 在完整页与 `QuickPanel` 之间条件渲染，同一个 `BoardClient` 留在上层。窗口大小由主进程控制，`show()` 会先把已展开窗口收回，再通知渲染器聚焦。前端仅重排布局不能改变这个行为。小窗的模式、选中项和绘图过程目前存在局部状态，迁移时须先决定状态由谁持有。 [应用入口](../src/main.tsx) · [小窗](../src/QuickPanel.tsx) · [窗口控制](../desktop/main.cjs)

| 分类 | 保留、重做或迁移范围 |
| --- | --- |
| 可保留 | Base UI Tabs/Dialog、Lucide 图标、命令面板语义与键盘逻辑；`drawing.ts` 几何、既有画板输入和导出；`FileStation` 的真实调用及维护操作；主题设置与减少动态效果。新视觉用样式和组合接入 |
| 重做 | 小窗外壳、品牌、主模式行、速记正文与最近入口、文件列表与详情、传输状态。将 `QuickPanel.tsx` 内打字、画图、文件逐步分离，避免一次替换整棵树 |
| 迁移 | `main.tsx` 的完整页从画板作为默认页调整为列表＋详情。画板、浏览器共享入口、设置、文件维护继续可达；先迁入独立前端区域，再切换入口 |
| 业务护栏 | 保持 `/api/board`、`/api/ops` 与 IPC 名称和 payload。保留便笺／笔迹 ID、坐标、版本、操作队列、冲突恢复、文件引用和回收／备份语义，保留 `%APPDATA%/arasn-notebook`。发布品牌改名与安装标识、单实例和数据迁移分开审批 |
| 需要联调 | 热键唤起和回焦点、窗口尺寸和多屏恢复、保存与恢复确认、真实文件进度、缩略图/完整预览、打开副本、互传发现及回执。主进程、preload 和 Worker 继续承担权限、持久化和文件流 |

### 接口与风险核对

| 边界 | 已有实现 | 实施约束 |
| --- | --- | --- |
| 窗口 | `app:info/layout/hide`，`onLayout/onFocus`，原生快捷键、托盘和单实例；`WindowManager` 记住窗体位置 | 第一批不改这些接口或回调。多屏恢复按实际窗体宽高夹紧仍需实测，窗口尺寸变更与样式切换分开评审 |
| 记录 | `edit` 合并排队，约 150 ms 防抖；`flush`、`recover`、版本与恢复队列已存在。保存状态是字符串，`pending`、`conflicts`、`error` 各自独立 | 不能从「正在保存」「已暂存」字符串推断恢复落盘。桌面恢复写入异步，服务确认与恢复失败都要核验。服务未就绪时 `edit` 会返回，若允许先输字必须有独立内存草稿及提交时机。原生快捷键直接隐藏，不能假定走过前端 `flush` |
| 文件 | `window.desktop.files` 已有 list/choose/drop/thumbnail/action/paste/progress。拖放由 preload `webUtils` 提取路径，服务持有真实文件并发布进度 | 小窗和展开只调用已存在的动作。缩略图 160×120，完整预览或系统打开没有现成接口。遇到无进度或无总字节的阶段使用不定进度，不按时间模拟百分比。扩展读取令牌、打开副本及取消需要独立审批 |
| 局域网 | `app:share` 启动旧白板共享。没有逐项设备发现、发送或接收任务 IPC | 局域网模式只能按能力显示。真实发送、加密配对、接收端写入和回执需要单独协议审批和两机验证。旧共享的关闭或退场也单独确认 |
| 样式与依赖 | `style.css → desk.css → interaction.css → lagoon.css` 多层覆盖。`LagoonMotion` 还会独立对图标运行动画 | XIGRA 样式作用域先落在小窗，检查 Portal 的主题继承和旧规则优先级。聚焦样式与动画各有明确归属，避免双重动画。按现有锁文件构建，无需新增框架、动画库或组件库 |

## 3. 按批开发任务

每批一个可评审、可回退的前端切片。入口切换前保留旧组件；任一时刻只挂载一套可编辑视图，共用现有 `BoardClient` 实例。下表路径标为「拟新增」的文件需等对应批次批准。影响主进程或接口的步骤按独立变更评审，不能随 UI 提交带入。

## 4. 执行与验收口径

1. 按 **1 → 2 → 3 → 4 → 5 → 6 → 7 → 8** 做可回退批次。先证明保存和文件闭环，再迁移入口。第 6 批前明确传输依赖；服务延期时，第 7 批按能力门禁验证布局，不把未启用传输算作验收通过。
2. 每批先记录范围和原表现，改动后执行 `npm run build` 与受影响回归。记录真实构建、测试命令、通过与失败原因，不能以旧截图或只看无横向滚动条代替验收。视觉批次核对实尺寸稿、字号、截断、焦点及亮暗主题。

4. 本轮 `tsc --noEmit` 通过。默认沙箱 `npm test` 出现 `rename EPERM` 和两项存储断言失败，同一命令经系统执行通道复核 8/8 通过。后续每批都记录执行环境。未运行正式构建、原生热键、多屏或新两机传输验收。
