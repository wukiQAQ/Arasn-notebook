## 共同设计约束

用户是频繁跨办公软件捕捉文字、草图与临时文件的人。第一任务是快速记下内容，第二是回找和暂存文件；界面优先级为内容、当前工具、文件、全局设置。探索容器的黑色比较栏不属于产品正式界面。

统一语义 token 为 `ground / panel / raised / ink / muted / line / accent / hover / note`，字体 10/11/13/15/17/21px，间距按 4/8/12/16/24/32px。Manrope 用于品牌，Segoe UI / Microsoft YaHei UI 用于操作和正文。Lucide 14–18px、1.65px 线宽；选中用结构边界与文字共同表达，不只靠颜色。焦点为 2px 强调色轮廓；命令框使用 Base UI 焦点约束与 Escape；拖柄可用方向键移动。

三种方案从布局、密度、内容材质与操作显隐上分开，不以更换配色充当三个方向。没有营销内容、虚构同步状态或背景循环动画。

## A · Precision Workspace

**概念：工具退到边界，内容保持精确。** 窄工具轨 → 固定顶部命令入口 → 中部画布 → 右侧文件检查器。适合高频键盘操作与大量文件切换。

- 色板：画布 `#181d1f`，表面 `#22282a`，浮层 `#2a3234`，正文 `#e7ece9`，次级文字 `#a1b0a9`，强调 `#a7cbb5`。
- 排版紧凑：13px 操作、15px 便签标题；4px 卡片转角、细分隔线；普通便签有独立页脚，选中便签有细边框和角标。文件检查器保持稳定宽度，浮动工具条置于画布上方。
- 交互：140–160ms 透明度/微位移；命令连续高亮；便签拖动无插值追赶鼠标，释放后恢复层级。
- 适配原因：最贴近当前命令、文件页和小窗架构，暗环境低干扰，固定操作位置学习成本低。
- 成本与风险：低至中。可逐模块替换视觉层；风险是窄屏需要折叠检查器、暗色状态和细线需保证对比度。辨识度较保守。

## B · Fluid Desktop

**概念：内容是一张桌面，工具按任务浮起。** 左侧独立浮动导航，中央开放画布，右侧可收起文件舱，底部上下文工具坞；没有贯穿整个窗口的传统侧栏。

- 色板：桌面 `#e9edf2`，面板 `#fcfdff`，抬升层 `#ffffff`，正文 `#293747`，次级文字 `#69788b`，强调 `#557ba0`。
- 17px 便签标题、13px 正文，较大呼吸空间；导航、便签和工具坞使用不同圆角与抬升关系。选中便签保留连续轮廓；导航提供此页便签索引。
- 交互：文件舱与便签以高阻尼弹簧进入；释放后吸附到 8px 网格；新增按钮仅图标产生微小磁性反馈，点击区域稳定；命令项共享高亮过渡。拖动中始终跟手，不对指针加弹簧。
- 适配原因：最符合快捷呼出、暂存、继续办公的节奏。浮层有清晰任务归属，也可迁移到小窗而不挤出内容。
- 成本与风险：中。需要管理浮层遮挡、焦点恢复和桌面/小窗布局；共享元素仅在命令高亮中验证，跨原生窗口过渡未实现，不应承诺无缝原生动画。

## C · Experimental Minimal

**概念：画布保持安静，文件像投入桌边的槽。** 横向品牌/导航，无完整侧栏；左侧极轻便签索引；工具在右上方，文件投递槽沿底部展开。

- 色板：纸白 `#f8f8f5`、便签 `#ffffff`、正文 `#282b29`、次级文字 `#74786f`、边界 `#dddfd7`、陶色 `#a55c3e` 强调。标题使用 Georgia / SimSun 的 21px 衬线字，操作仍为无衬线，建立纸面与软件控件的区别。
- 普通便签接近纸张，选中便签以侧边色条表达；卡片操作在靠近、选中或键盘聚焦时显示。文件采用横向收纳条而非纵向检查区。
- 交互：卡片拖动有抬升，投递区域在文件进入后显示整区反馈；真实读取完成后文件条目才进入收纳位置。命令框保持可搜索、可键盘操作，不使用打字装饰动画。
- 适配原因：便签与文件投入具有产品记忆点，画布最完整，适合轻量捕捉。
- 成本与风险：中至高。隐藏操作的发现性、横向文件数量增长、窄屏投递槽占高都需继续用户验证。没有把它做成依赖悬停才能使用的软件。

## 动效规则与性能边界

Motion 为唯一动效库，`MotionConfig reducedMotion="user"` 加 CSS `prefers-reduced-motion`。命令入场为 y=6px、scale=.985 到 1、透明度变化；快速操作约 140–180ms。命令高亮使用 stiffness=650 / damping=45；B 卡片 stiffness=380 / damping=32，文件舱 340/32。弹簧实际收敛时间随位移变化，不把 duration 当成物理弹簧总时长。

画布/便签拖动通过 MotionValue 更新 transform，避免每帧整页 React 重绘。画笔路径目前随输入更新 React，适用于探索，不代表长草图性能已验收。拖动抬升仍有短时阴影插值，正式实施应实测绘制成本。缩放/平移流畅性由交互测试覆盖，未取得帧率或硬件性能结论。模拟隐藏不会操作系统窗口；原生焦点和窗口动画留待所选方案实施。

## 评审建议

| 方向 | 独特性 | 使用方式 | 动效取向 | 功能适配 | 维护成本 |
| --- | --- | --- | --- | --- | --- |
| A | 克制、相对熟悉 | 键盘与固定工具位置 | 快而短 | 现有功能最直接 | 低至中 |
| B | 桌面浮层有空间感 | 任务浮起、便签与文件并置 | 高阻尼、吸附 | 更适合呼出和暂存 | 中 |
| C | 纸面与投递槽最鲜明 | 内容优先、操作渐显 | 抬升、收纳 | 大文件库需再设计 | 中至高 |

推荐 **B 为主体方向**：最符合轻盈、快速呼出与独立桌面工具的定位；A 适合明确偏好高密度深色的用户，C 适合优先追求差异化捕捉体验。此推荐是设计判断，不是用户测试结论。等用户选择，再进入正式分模块实施。
